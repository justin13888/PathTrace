# EXP-0003: Independent Python reader and Rust reader agree on the v1.0 conformance corpus

- verdict: pass
- pinned commit: see `manifest.toml` (396bbb8)
- requirements: REQ-FMT-001, -002, -003, -005, -009, -010, -013, -014, -018

## Hypothesis

A reader written only from `docs/design/ptf-format.md`, sharing no code with the Rust implementation, reaches the same verdict as the Rust reader on every case of the conformance corpus. It must accept the valid files with identical content digests and reject the invalid files for the expected reason.

## Method

The corpus is `conformance/v1.0/`, 18 files plus `expected.json`, generated by `cargo xtask corpus`:

- **Valid (6)**: minimal; every type and encoding combination, including nullable, extreme values and every column encoding; uncompressed with no index; zstd-compressed with 100 k rows; an unknown non-critical section; and a synthetic *future minor version* (minor 7, unknown column type and encoding, unknown table, column and head keys, and an unknown section with unknown flag bits).
- **Invalid (12)**: bad magic, higher major, file flags, truncation, CRC, unknown critical section, unknown flag on a critical section, META not first, non-canonical CBOR key order, a column blob with a trailing byte, a decompression bomb, and a wrong INDX hash.

1. `tools/ptf-py/ptf.py conformance`: pure Python 3.14 standard library, with CRC32C and BLAKE3 implemented from their specifications.
2. `cargo test -p pt-format --test conformance`: the Rust reader against the same `expected.json` (verdict, content digest and error kind), plus a JSON-twin round trip of every valid file.

## Result

`artifacts/stdout.log`: **18/18 cases pass** in the Python reader. The Rust conformance tests pass (2/2). The compressed and uncompressed encodings of the same tables have the same content digest (`c3327c73…`), so the digest is independent of compression.

## Interpretation

- The specification is complete enough to implement PTF without our code (REQ-FMT-018).
- The future-minor file shows that today's readers keep accepting files that later minor versions extend with sections, columns and keys (REQ-FMT-009, REQ-FMT-010).
- The invalid cases show that both readers enforce the critical-section rule, the limits and the integrity checks for the same reasons.
- Not covered: real traces in the corpus. Real traces from the probe were also read by the Python reader during development; adding a redacted real trace as a golden file is part of the release step.
