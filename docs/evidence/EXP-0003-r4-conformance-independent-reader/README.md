# EXP-0003-r4: Independent and Rust readers agree on every conformance directory, incl. the v1.1 corpus

- verdict: pass
- pinned commit: see `manifest.toml`
- supersedes: [EXP-0003-r3](../EXP-0003-r3-conformance-independent-reader/) (passed; went stale when PTF 1.1 changed `crates/pt-format/src` and `docs/design/ptf-format.md`)
- requirements: REQ-FMT-001, -002, -003, -005, -009, -010, -013, -014, -018

## Method

Same command as r2 and r3. The Python reader now runs over three directories: `conformance/v1.0` (18 synthetic cases), `conformance/v1.0-real` (1 real, anonymised IPv6 capture) and the new `conformance/v1.1` (3 cases, generated by `cargo xtask corpus`): a minimal file with header minor 1, and a small merged trace carrying every 1.1 raw column, table and META/FLOW key (`pkt.rxq_drops`, `dup` with `rx_src`/`size`/`rxq_drops`, `txts_unmatched`, `pairs.boot`, `exchange` nonces, `netstack`, `qdisc`, `endpoints.<ep>.sockets`/`qdisc`/`txqueuelen`, `session.<ep>.t0_boot`, `merge_checks`, FLOW `max_bytes`), written once compressed with an index and once uncompressed without one. The Rust conformance tests check every directory's verdicts, and the JSON twin round trip now covers v1.0 and v1.1.

## Result

18/18, 1/1 and 3/3 cases pass (`artifacts/stdout.log`), and both Rust conformance tests pass. Every v1.0 and v1.0-real content digest is identical to r3; regenerating the corpus left `conformance/v1.0` byte-identical (REQ-FMT-010). Both encodings of the 1.1 trace have the same content digest (`d1182c01…`), as the digest is compression- and index-independent.

## Interpretation

A reader written only from ptf-format.md reads the PTF 1.1 additions with the same content digest as the Rust reader, and the 1.0 corpus still reads unchanged under the 1.1 reader. The 1.1 golden files are format fixtures: their values are consistent with the tables' meaning but they are not a derivation test (ground truth for the 1.1 behaviour is EXP-0002-r9).
