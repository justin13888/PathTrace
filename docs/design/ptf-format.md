# PTF: Path Trace Format, version 1.0

- requirements: REQ-FMT-001 … REQ-FMT-022, REQ-PRB-033
- adr: 0008, 0009, 0011, 0014
- research: R-0001, R-0002, R-0005, R-0007, R-0017

This document is the normative specification of PTF 1.x (currently 1.3). An independent implementation must be possible from this document alone (REQ-FMT-018); `tools/ptf-py/` is written only from it. Keywords MUST, MUST NOT, SHOULD and MAY are used as in RFC 2119.

A 1.1 reader reads 1.0 files: a column or table that is absent was not recorded by that version, which is different from a recorded zero or null. A 1.0 reader reads 1.1 files by skipping what it does not know.

Golden files: `conformance/v1.0` holds the 1.0 corpus, `conformance/v1.1` the 1.1 corpus, `conformance/v1.2` the 1.2 corpus and `conformance/v1.3` the 1.3 corpus, all generated with `cargo xtask corpus`; the 1.1 corpus's `valid-1-1-additions*.ptf` carry the 1.1 columns, tables and META/FLOW keys of the table above (EVNT types are open strings and need no golden file), the 1.2 corpus's `valid-1-2-additions*.ptf` carry every 1.2 addition (a macOS initiator reaching a Linux responder through a tunnel, with `power_assertion` and a tunnel `iface_change` as example events and a PATH and PLCY qualified by the overlay), the 1.3 corpus's `valid-1-3-additions*.ptf` carry every 1.3 addition, and `tools/ptf-py` reads every directory (EXP-0003-r4). The existing directories never change.

The 1.3 additions are non-critical in the same way. The 1.2 additions are all non-critical: a 1.1 reader skips the unknown table, column and keys of a 1.2 file and reads the rest, and a 1.2 reader reads a file without them as one recorded before they existed. No existing column or key changes meaning; in particular `tcpinfo` keeps meaning Linux `struct tcp_info` and the clock domain kinds keep their names.

The header minor is the highest minor whose additions the file may contain, in any layer. Re-deriving (`derive`, `merge`, `trace redact`) a file of an older minor writes the derived layer with the current tool and raises the header minor to the tool's (a 1.0 file becomes 1.1), because the new derived sections may use 1.1 additions; its raw layer keeps what it had, so a 1.1 raw column or table can still be absent from such a file. The minor of the tool that captured the raw layer is not recorded separately: `META.tool` (or `captured_by`) names the capturing pathtrace version, which maps to the minor in the table above.

Part I gives the design principles and the decision behind each. Part II is the byte-level specification. Part III defines the sections.

# Part I: design principles

PTF holds three content layers, which are kept apart:

| Layer | Sections | Mutability |
|---|---|---|
| **raw**: what was observed | META, FLOW, CLOK, OBSV, CTXS, EVNT | Immutable after capture. Only redaction removes data, and it records doing so |
| **derived**: the path model | PATH, SERS, PLCY, VALD | Regenerated by `pathtrace derive` from the raw layer at any time |
| **integrity** | INDX | Recomputed on every write |

The file is hierarchical: file → sections → (CBOR head → tables → columns). Provenance is a chain that can be followed down: a PATH field names its `method` and version, its `confidence`, and the raw tables and time range it came from. META names the tool version and git commit that wrote the raw layer, and PATH names the ones that derived the model.

Each principle below follows Problem / Choice / Rationale / Validated by.

### P1. The raw layer is never corrected in place
- **Problem**: clock-offset and skew estimation, and every derivation method, will improve after capture.
- **Choice**: raw timestamps are stored exactly as obtained, in the clock domain that produced them (declared per column). Corrections are derived data (the clock model in PATH) and are applied at read time.
- **Rationale**: a capture cannot be repeated. Any in-place correction would freeze today's algorithm into the data.
- **Validated by**: derive idempotence test (raw sections byte-identical after `derive`), EXP pending.

### P2. Columnar encoding where the volume is
- **Problem**: per-packet observations dominate the file size (hundreds of thousands of rows per session), while metadata is a few kilobytes.
- **Choice**: bulk data lives in *tables* of typed columns. Each column has its own encoding (`plain`, `varint`, `delta`, `delta2`, `rle`, `bitmap`) and the section payload is then zstd-compressed. Metadata is CBOR with text keys.
- **Rationale**: a column of near-constant deltas (send times of a paced flow, sequence numbers, sizes) shrinks to a byte or less per row before general compression. Text keys keep small metadata self-describing at negligible cost.
- **Validated by**: encoding bake-off (EXP-0001): JSONL+zstd, CBOR rows+zstd, Arrow IPC+zstd and PTF columnar+zstd, compared on bytes per packet, CPU, memory and dependencies.

### P3. Explicit space budget
- **Choice**: the raw per-packet layer costs at most 8 bytes per packet after compression. A `standard` session file is at most 10 MB at 100 Mbit/s or below, and writers use bounded memory.
- **Rationale**: traces are collected by the hundred and synced over poor links. Size must stay far below the data the probe spends to obtain them.
- **Validated by**: EXP-0001 and the per-profile size experiment after the probe lands.

### P4. Lossless integer precision
- **Choice**: raw values are integers: nanoseconds, bytes, bit/s, counts. Floating point appears only in derived parameters. Timestamps keep nanosecond resolution.
- **Rationale**: kernel timestamps have nanosecond resolution, and truncating them is irreversible. With delta coding, unused precision costs little (measured in EXP-0001).

### P5. Absence is explicit
- **Choice**: nullable columns carry a validity bitmap. A missing receive time means "not received or not known", never 0. Capacity segments carry a quality of `saturated`, `estimated` or `unknown`. Every PATH field has a `status`.
- **Rationale**: draft spec §6.5: periods without evidence are unknown, never zero.

### P6. Forward compatibility at three levels
- **Choice**: unknown non-critical sections are skipped; unknown columns are skipped; unknown CBOR map keys are ignored. Names and keys are never reused with a different meaning. A minor version only adds.
- **Rationale**: "capture accurately today, add data points tomorrow" (ADR 0008). A newer probe adds columns, keys or sections, and older readers keep working.
- **Validated by**: a synthetic "future minor" file in the conformance corpus.

### P7. Crash safety
- **Choice**: a per-endpoint observation log is the same container (`META.kind = "obslog"`), written append-only as self-contained chunk sections (about 1 s or 1 MiB each), each flushed and fsync'd. Every section has a CRC32C. A reader stops at the first incomplete or corrupt section and keeps everything before it.
- **Rationale**: laptops sleep and batteries die. At most the chunk in flight is lost.
- **Validated by**: a truncation experiment (every byte offset) and fuzzing.

### P8. Canonical encoding and a content digest
- **Choice**: a canonical writer produces identical bytes for identical content (deterministic CBOR, fixed chunking, fixed compression level). The **content digest** is BLAKE3 over the *uncompressed* section records, so it does not depend on the zstd version or level.
- **Rationale**: golden files and evidence manifests need stable identifiers. Compressed bytes can differ between zstd library versions, but uncompressed canonical payloads cannot.

### P9. Integrity matched to the failure
- **Choice**: CRC32C per section catches torn writes and bit rot cheaply. BLAKE3 of the file prefix in INDX gives identity and tamper evidence. SIGN (deferred, #12) would give authenticity.

### P10. Safe on hostile input
- **Choice**: compressed sections declare their uncompressed size. Readers enforce caps (default: 1 GiB per section, 4 GiB per file), a CBOR nesting limit (32), and check every length before allocating.
- **Rationale**: traces will be shared publicly (REQ-FMT-016).

### P11. A lossless text twin
- **Choice**: a JSON Lines dump with one object per section. Columns appear as arrays of decoded values; the column encodings are recorded alongside so that `load` re-encodes byte-identically, even for unknown sections and columns.

### P12. Self-describing units and provenance
- **Choice**: each column declares `unit` and `clock`. META declares clock domains, the tool and its commit, timestamp sources and redaction level. PATH fields carry `method` (`name/N`), `confidence` and `source`.

### P13. Privacy by construction
- **Choice**: each identifying item is tagged where it lives: columns with `pii`, CBOR values through a `pii` map of JSON Pointers in the same section head. Classes are `id` (directly identifying) and `quasi` (identifying in combination). Redaction is generic and needs no per-field code.

### P14. Derived sections are marked as derived
- **Choice**: section flag bit 2 (`derived`). A tool that changes raw data MUST drop or regenerate every derived section. Analogous to PNG's safe-to-copy bit (R-0007).

# Part II: byte-level specification

All integers are little-endian. "u16" means an unsigned 16-bit integer, and so on.

## 1. File header (16 bytes)

| Offset | Size | Field | Value |
|---|---|---|---|
| 0 | 8 | magic | `89 50 54 46 0D 0A 1A 0A` |
| 8 | 2 | major | `1` |
| 10 | 2 | minor | `1` (writers of PTF 1.1; readers accept any value) |
| 12 | 4 | flags | `0`. Readers MUST reject a file with any flag bit set (reserved for future major versions) |

A reader MUST reject a file whose `major` is greater than the highest major it supports, and MUST accept any `minor` (P6). The magic follows PNG's design: a non-ASCII first byte, CR-LF and LF to detect line-ending mangling, and Ctrl-Z.

## 2. Section record

Sections follow the header back to back until end of file.

| Offset | Size | Field |
|---|---|---|
| 0 | 4 | `type`: four bytes, each `A`–`Z` or `0`–`9` |
| 4 | 2 | `flags` |
| 6 | 2 | `reserved`: MUST be 0 when written. A reader treats a non-zero value like an unknown flag bit |
| 8 | 8 | `length`: byte length of `payload` as stored |
| 16 | `length` | `payload` |
| 16+length | 4 | `crc`: CRC32C (Castagnoli) over bytes 0 … 16+length−1 of this record (header and stored payload) |

Section flags:

| Bit | Name | Meaning |
|---|---|---|
| 0 | critical | A reader that does not know `type` MUST reject the file. If clear, it MUST skip the section |
| 1 | zstd | The stored payload is `u64 uncompressed_length` followed by one zstd frame |
| 2 | derived | The section is derived from the raw layer (P14) |
| 3–15 | reserved | Unknown bits set: reject the file if the section is critical, skip the section otherwise |

Section-order rules:
- `META` MUST be the first section.
- `INDX`, if present, MUST be the last section.
- Section types MAY repeat where Part III says so (for example, OBSV chunks). Repeated sections of the same type are interpreted in file order.

Truncation and corruption: when a record is incomplete (end of file inside it) or its CRC mismatches, a strict reader (`trace check`) reports an error. A recovering reader (used for observation logs) MUST stop there and expose all preceding complete sections.

## 3. Section payload (generic)

After decompression, every section payload defined by PTF 1.0, and every future section, MUST have this structure:

```
payload := head_length:u32  head:CBOR(head_length bytes)  blob*
```

- `head` is a single CBOR map in the deterministic profile (§4).
- If `head` contains the key `"tables"`, the payload continues with the column blobs of those tables, in table order and then column order, each exactly `len` bytes (§5). Otherwise the payload ends right after the head.
- Trailing bytes after the last blob are an error.

This generic structure lets any reader dump, redact or copy sections it does not understand.

## 4. Deterministic CBOR profile

Heads are CBOR (RFC 8949) restricted to:
- major types 0 (uint), 1 (negative int), 2 (byte string), 3 (text string, valid UTF-8), 4 (array), 5 (map), and 7 with values `false`, `true`, `null`, and 64-bit floats only (additional info 27);
- definite lengths only; integers and lengths in their shortest form;
- map keys are text strings that do not begin with `$` (reserved for the JSON twin's tags, §P11), unique within a map, sorted by their encoded bytes (bytewise lexicographic, which for text keys means shorter keys first, then by bytes: RFC 8949 §4.2.1 core deterministic ordering);
- no tags, no `undefined`, no half or single floats, no NaN with payload (NaN MUST be encoded `0xfb7ff8000000000000`);
- nesting depth at most 32.

Writers MUST produce this profile. Readers MUST reject heads that violate it (to keep encoding canonical, which the digest depends on).

The CDDL for every head is in `docs/design/ptf-1.0.cddl`.

## 5. Tables and columns

A head may declare tables:

```
"tables": [ table, ... ]
table := { "name": tstr, "rows": uint, "columns": [ column, ... ], ? "attrs": { * tstr => any } }
column := {
  "name": tstr,          ; unique within the table
  "type": "u64" / "i64" / "f64" / "bool",
  "enc":  "plain" / "varint" / "delta" / "delta2" / "rle" / "bitmap",
  "len":  uint,          ; blob byte length
  ? "nullable": bool,    ; default false
  ? "unit": tstr,        ; e.g. "ns", "B", "bit/s", "count", "dBm", "ppb", "enum"
  ? "clock": tstr,       ; clock domain id (META.clocks) for time columns
  ? "enum": [ * tstr ],  ; for unit "enum": value i means enum[i]
  ? "pii": "id" / "quasi",
  ? "desc": tstr,
}
```

Readers MUST ignore unknown keys in `table` and `column` maps. A reader that does not know a column's `name` MAY skip it using `len`. A reader that does not know a column's `type` or `enc` MUST skip that column and MUST NOT fail the file.

### Column blob

```
blob := [validity]  values
validity := ceil(rows / 8) bytes, present iff nullable; bit i (LSB-first within byte i/8) = 1 if row i is present
values   := encoding of the present values only, in row order (n = number of present rows)
```

### Encodings

LEB128 below means unsigned LEB128. zigzag(x) = `(x << 1) ^ (x >> 63)` on i64.

| enc | Types | Encoding of n values |
|---|---|---|
| `plain` | u64, i64, f64 | n × 8 bytes, little-endian (IEEE 754 binary64 for f64) |
| `plain` | bool | not allowed (use `bitmap`) |
| `bitmap` | bool | ceil(n/8) bytes, LSB-first |
| `varint` | u64 | n × LEB128(v) |
| `varint` | i64 | n × LEB128(zigzag(v)) |
| `delta` | u64, i64 | LEB128(zigzag(d_i)) for i in 0..n, where d_0 = v_0 and d_i = v_i − v_{i−1} (wrapping, as i64) |
| `delta2` | u64, i64 | LEB128(zigzag(e_i)), where e_0 = v_0, e_1 = v_1 − v_0, e_i = (v_i − v_{i−1}) − (v_{i−1} − v_{i−2}) (wrapping, as i64) |
| `rle` | u64, i64 | runs: LEB128(zigzag(value)) LEB128(run_length ≥ 1) …, run lengths summing to n |

For `u64` columns, values are reinterpreted as i64 (two's complement) before differencing or zigzag, and back after decoding, so the full u64 range round-trips. The writer chooses the encoding per column; any encoding valid for the type is conformant. The canonical writer's choices are given in §7.

A reader MUST reject a blob whose decoding does not consume exactly `len` bytes or does not yield exactly n values.

## 6. Clock domains

META declares the clock domains that time columns refer to:

```
"clocks": { "a.mono": {...}, "a.real": {...}, "b.mono": {...}, "b.real": {...} }
domain := { "kind": "monotonic_raw" / "realtime" / "tai" / "trace", ? "endpoint": "a" / "b", ? "pii": ... }
```

- `a` is the initiator and `b` the responder.
- Raw time columns hold the domain's own nanosecond value (for `realtime`, nanoseconds since the Unix epoch).
- The derived `trace` domain is defined by PATH's clock model: nanoseconds since session start on the initiator's monotonic clock (`a.mono` minus `META.session.t0_a_mono`).
- Realtime values reveal when a capture happened, so `realtime` domains are `pii: "quasi"` (§9).
- `monotonic_raw` is a monotonic clock that is not slewed or stepped by time synchronisation and does not advance while the host is suspended; `realtime` is the host's wall clock (slewed and stepped). Derivation relies on these properties, not on a particular OS clock.
- 1.2: a domain MAY carry `source`, the OS clock it was read from: `CLOCK_MONOTONIC_RAW` and `CLOCK_REALTIME` on Linux, `mach_absolute_time` and `CLOCK_REALTIME` on macOS (probe.md §9.1). A domain without `source` (1.0, 1.1) was read from the Linux clocks.

## 7. Canonical writer

A canonical PTF file (REQ-FMT-012) is produced by a writer that:
1. emits sections in this order: META, FLOW, CLOK, OBSV…, CTXS…, EVNT, PLCY, PATH, SERS…, VALD, then sections unknown to it in their original relative order (just before INDX), then INDX;
2. splits OBSV and SERS tables into chunks of 65 536 rows (the last may be shorter). Value chosen by EXP-0001;
3. compresses every section whose uncompressed payload exceeds 256 bytes, with zstd level 19 (EXP-0001), without dictionary, checksum or content-size flag (the size is in the PTF prefix). The level is fixed by the specification for canonicality;
4. chooses column encodings from a fixed table per known column (§Part III); unknown columns keep their original encoding;
5. writes INDX.

Observation logs (`kind = "obslog"`) are not canonical: they use zstd level 3 and time-based chunking, optimised for safe streaming. `merge` turns two logs into one canonical trace.

## 8. Content digest

`content_digest = BLAKE3( for each section except INDX, in file order: type(4) ‖ (flags & ~0x0002)(u16) ‖ u64(uncompressed payload length) ‖ uncompressed payload )`.

The zstd bit is masked out, so the digest identifies content, not its compression. It is written as 64 lowercase hex characters in INDX and is what evidence manifests and golden-file tests cite.

## 9. Privacy annotations and redaction

- Columns: `"pii": "id" | "quasi"`.
- CBOR heads: an optional key `"pii"` mapping RFC 6901 JSON Pointers (relative to the head) to `"id"` or `"quasi"`, for example `{"/network/label": "id", "/network/asn": "quasi"}`.
- `redact --level shareable` removes `id` items. Pointed-to map entries are deleted, pointed-to array elements become `null`, and `pii` columns are dropped (with table attrs updated) in every section, including unknown ones.
- `redact --level anonymous` also removes `quasi` items and shifts every `realtime` domain so that the session starts at 1970-01-01T00:00:00Z, recording `"shifted": true` on the domain.
- META `redaction` records the level (`full`, `shareable`, `anonymous`). Redaction never adds information, and derived sections are regenerated afterwards.

## Raw tables (trace, after merge)

Every table has `attrs.dir` (`a_to_b` / `b_to_a`) or `attrs.endpoint` (`a` / `b`). Time columns declare their clock. Rows of the same table name and attrs across chunks concatenate in file order.

| `wifi` (CTXS) | endpoint=a | t, freq MHz, width enum (nl80211), signal dBm, beacon_signal dBm, tx/rx bitrate (100 kbit/s), tx_retries, tx_failed, bss (hash, pii quasi): all nullable |

FLOW lists every flow (kind, sender, socket, class, pattern, TOS policy, QUIC shaping, echo). EVNT holds observed events (`phase_start`, `peer_addr`, `nat_rebind`, `addr_new`/`route_*`/`link_*`, `icmp`, `local_error`, `send_error`, `tcp_probe`, `saved_syn`, `ref_tcp`, `flow_stopped`, `budget_cap`, `light_paused`, `session_end`, …); identifying values are wrapped `{value, pii}` and listed in the head's `pii` map.

Observation logs (`META.kind = "obslog"`) carry the per-endpoint precursors: `tx` (sock, flow, seq, size, phase, train, train_idx, tos_tx, id = OPT_ID, tx_intended, tx_user_lag), `txts` (sock, id, kind enum[sched, snd], real) and `rx` (sock, flow, seq, size, rx, rx_src, tos_rx, ttl_rx, src, rxq_drops). Any non-META section may repeat in logs. `merge` joins `tx`+`txts` by (sock, OPT_ID) and then with the peer's `rx` by (flow, seq) into `pkt`.

What `merge` keeps. Every logged row ends up in the trace: each `tx` row is one `pkt` row, the first arrival of its (flow, seq) fills that row's receive columns, `dup` holds the later arrivals, `unmatched` the arrivals with no transmission (also when only the initiator's log is merged), `echo` an endpoint's arrivals of its own probes, and `txts_unmatched` every stamp `pkt` does not hold. A `pkt` or `dup` column keeps the metadata of the log column it comes from (`desc`, `pii`, `enum` and any other key), with `unit` and `clock` as in the table above. A `tx` column merge does not know is carried into `pkt` as `tx.<name>`, and an `rx` column as `rx.<name>` in `pkt` and `dup` (a later minor that adds a `tx` or `rx` column names its `pkt` column this way); `unmatched` and `echo` keep every `rx` column under its own name. Other log tables are copied with every column, in the section kind they were logged in (`pairs` and `exchange` in CLOK, the context tables in CTXS). A table merge cannot re-chunk without loss (a column that is not an integer, a column whose type or metadata differs between chunks, or a table directory key other than `attrs.endpoint` naming its own endpoint) is copied chunk by chunk unchanged; a `tx`, `txts`, `rx` or `pairs` table among them is also read for the join. A log section other than META, FLOW and EVNT that has a head, is not a generic table section or is of another kind is copied unchanged, and the join does not read its tables.

What `merge` does not keep, so the `.ptflog` pair stays the complete record and SHOULD be archived with the trace: the OPT_ID a `tx` row was logged with (`pkt` holds the stamps joined under the re-anchored id, probe.md §4.1, so neither the `tx`–`txts` join nor its re-anchoring can be redone from the trace alone); the responder log's META `trace_id`, `created_utc` and `network` (the initiator's are kept; `kind` and `role` follow from `merged_from`; the trace's `redaction` is the level both logs record, and `full` when they differ or one records none); the initiator's declaration of a clock domain the responder's log also declares (the responder's is kept; each pathtrace log declares only its own endpoint's domains); for a flow id both logs define, the responder's definition (the initiator's is kept); FLOW and EVNT head keys other than `flows` and `events` (EVNT `pii` is regenerated); and the order and chunking of rows (`pkt` is in (flow, seq) order).

`rxq_drops` is the receiving socket's cumulative drop count (`SO_RXQ_OVFL`) when the datagram was queued: it increases between two arrivals on a socket exactly when that socket dropped datagrams in between. It is null where the socket could not enable the option. How OPT_IDs were assigned is recorded per socket in `META.endpoints.<ep>.sockets[].tx_ids` (`explicit`: exact; `predicted`: inferred, failures recorded as events, and `merge` re-anchors the ids after each failure against the stamp times, counted in `merge_checks` as `tx_reanchors_<ep>` and `tx_reanchored_<ep>`; `none`: no TX stamps), probe.md §4.1.

META keys added in 1.2 (probe.md §9), all optional; a reader that finds one absent treats the fact as not recorded, never as false or zero:

| Key | Values | Meaning |
|---|---|---|
| `endpoints.<ep>.os_family` | `linux`, `darwin` (open string) | The endpoint's platform. `os` stays a display name and `kernel` the kernel release (on macOS the Darwin release) |
| `endpoints.<ep>.os_version` | text | OS version: `VERSION_ID` of `/etc/os-release` on Linux, the macOS product version (e.g. `15.6`) on macOS |
| `endpoints.<ep>.iface.tunnel` | `{kind: tstr, provider: tstr / null}`, absent when not a tunnel | The egress interface toward the peer is a tunnel: `kind` is the Linux link kind (`wireguard`, `tun`, …) or the macOS interface name prefix (`utun`, …); `provider` is a hint (`tailscale`) or null. `iface.mtu` is then the tunnel's MTU. `iface_change` events carry the same key in their `iface` detail |
| `endpoints.<ep>.sockets[].icmp_errors` | bool | The socket can observe ICMP errors (Linux `IP_RECVERR`: `true`; macOS: `false`). When `false`, the absence of `icmp` events from that endpoint is not evidence that no ICMP error arrived |

On macOS a socket also records `kernel_tx: false`, `tx_ids: "none"` and `rxq_ovfl: false`, values 1.1 already defines. The derived layer adds `PATH.overlay` (method `overlay.egress-iface/1`: `overlay` bool, `endpoints`, `kind`, `provider`, `mtu`, `overlay_ns`) and the key `overlay_limited: true` on the PLCY class entries and the per-direction `policer`, `mtu`, `ecn` and `dscp` fields when `overlay` is true (probe.md §9.9). A derived field whose input the platform could not observe has status `unknown` and a `reason`, and carries no count (P5).

META keys added in 1.3 (probe.md §4.5, ADR 0015), all optional and generic. Each endpoint writes its own, and absence means not recorded:

| Key | Values | Meaning |
|---|---|---|
| `endpoints.<ep>.clock_sync` | `{status: "synced" / "unsynced" / "unknown", est_error_us: int / null, max_error_us: int / null}` | Kernel NTP state when the log started (`adjtimex`). macOS: `unknown`, errors null |
| `endpoints.<ep>.power` | `{source: "ac" / "battery" / "ups" / "none" / "unknown" / tstr, low_power: bool / null}` | Power source and low-power mode when the log started |
| `endpoints.<ep>.pacing` | `{best_late_ns: uint / null, policy_error: tstr / null, background: bool / null}` | Least wake lateness of five 2 ms pacer-like sleeps, the error from requesting the pacing scheduling policy, and the macOS background policy (always false on Linux); `best_late_ns` and `background` are null and `policy_error` holds the error when the check could not run |
| `endpoints.<ep>.underlay` | iface map as `iface` (without `tunnel`) / null; absent when `iface` is not a tunnel | The interface the default route of the session's address family uses beneath the tunnel; `name` is `pii: quasi` |

EVNT types added in 1.3: `host_state {clock_sync, power}` (values as the META keys, when either changed; checked every 10 s) and `underlay_change {from, to, iface}` (names `pii: quasi`, `iface` as `underlay` without `name`). CTXS table `ifstats_underlay` (1.3): columns and encodings as `ifstats`, for the underlay interface. Its counter series restarts at each `underlay_change`.
